# K-th

## 1. Корректность решения

`find_kth_largest(nums, k)` находит k-е число по убыванию с учётом повторов. Места считаются с единицы. Функция работает на копии списка и использует quickselect. [Решение](kth.py)

## 2. Объяснение решения

Искомый индекс равен `k - 1`. Выбираем случайное опорное число и делим текущий отрезок на три группы. Сначала идут числа больше опорного, затем равные ему и в конце меньшие. Теперь известны все места, которые занимают копии опорного числа. Если нужный индекс среди них, ответ найден. Иначе повторяем разбиение только в той части, где остался этот индекс.

## 3. Оценка сложности

Один проход по отрезку длины m занимает O(m). Если опорное попало в среднюю половину по величине, для поиска останется не больше 3m/4 элементов. В среднем для такого сокращения хватает двух проходов. Поэтому ожидаемое время пропорционально сумме n + 3n/4 + (3/4)²n + …, то есть O(n). В худшем случае отбрасывается по одному элементу, и время достигает O(n²). Копия списка занимает O(n) памяти, для самого поиска хватает O(1).

## 4. Визуализация работы алгоритма

Для `[3, 2, 3, 1, 2, 4, 5, 5, 6]` и `k = 4` ищем индекс 3. Вот один возможный ход поиска при выборе опорных чисел 6, 3 и 5.

| Опорное | Список после разбиения | Где искать индекс 3 |
| ---: | --- | --- |
| 6 | `[6, 3, 1, 2, 4, 5, 5, 2, 3]` | Шестёрка занимает индекс 0. Остаются индексы 1–8. |
| 3 | `[6, 5, 4, 5, 3, 3, 2, 2, 1]` | Тройки стоят на индексах 4 и 5. Остаются индексы 1–3. |
| 5 | `[6, 5, 5, 4, 3, 3, 2, 2, 1]` | Пятёрки стоят на индексах 1 и 2. На индексе 3 осталась **4**. |

## 5. Тесты

Два примера из условия дают 5 и 4. Есть проверки для одного элемента, первого и последнего мест, позиции внутри блока повторов и списка из одинаковых чисел. Пустой список, k = 0 и k больше длины списка дают `ValueError`, дробное k даёт `TypeError`. [Тесты](test_kth.py)
